# Embedded knowledge notes

## Reading RM0008 (reference manual)

Register addresses aren't guessed — derived from the manual, in order:

1. **Bus map** ("Memory map" chapter, Table 3) — gives each peripheral's
   base address and which bus it's on (AHB / APB1 / APB2).
2. **Peripheral register map** (per-peripheral chapter, last section,
   e.g. "GPIO and AFIO register maps") — table of register offsets from
   that peripheral's base.
3. **Bit-field diagram** (per-register, right above its register-map entry)
   — what each bit/field in that register actually does.

`address = peripheral base (step 1) + register offset (step 2)`, bit meaning
from step 3.

Datasheet ≠ reference manual: datasheet has pinout/electrical specs,
reference manual (RM0008) has the register map. Different documents.

## Keywords

- **RCC** (Reset and Clock Control) — gates power/clock to every other
  peripheral. Peripherals boot with clocks OFF; must enable in RCC first or
  writes to that peripheral's registers silently no-op.
- **APB2ENR** — RCC's clock-enable register for APB2-bus peripherals
  (GPIOA-G, USART1, SPI1, timers...). One bit per peripheral, `1`=on.
  `IOPCEN` = bit 4 = GPIOC's clock.
- **GPIOx** — one GPIO port (x = A..G), 16 pins each.
- **CRL / CRH** — port configuration registers, low half (pins 0-7) / high
  half (pins 8-15). 4 bits per pin: 2-bit MODE (speed/input) + 2-bit CNF
  (push-pull, open-drain, analog...).
- **ODR** — Output Data Register, direct mirror of all 16 pins' output
  state. Read = current level. Write = read-modify-write, not atomic —
  race-prone if an interrupt touches the same port.
- **BSRR** — Bit Set/Reset Register, write-only. Low 16 bits set a pin high,
  high 16 bits (bit+16) reset it low. Single atomic write per pin, no race.
  Preferred over ODR for changing pin state.
- **volatile** — required on all register pointers; tells the compiler the
  value can change/matter outside its own control flow, so it can't cache,
  reorder, or optimize away the access.

## Project 1 — `01_flashing_led_port`

Blinks the onboard LED (PC13, active-low), everything hardcoded:
`RCC_APB2ENR`, `GPIOC_CRH`, `GPIOC_BSRR` as fixed addresses computed by
hand from the manual. Minimal vector table (SP + `Reset_Handler` only, no
interrupts used). Goal: get one register-level write working end to end —
clock enable, pin config, pin toggle, flash, see it blink.

## Project 2 — `02_flashing_led_port_user_defined`

Same blink, generalized: `LED_PORT`/`LED_PIN` are `#define`s, register
addresses computed from them (`base = 0x40010800 + port_index*0x400`,
clock-enable bit = `port_index+2`, CRL vs CRH picked by `pin < 8`). Goal:
turn the one-off arithmetic from project 1 into a reusable formula, confirms
understanding of *why* the addresses are what they are, not just what they
are.
